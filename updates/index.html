v0.9.8Stable baseline3 November 2026⌄

Established GitHub version-control baseline and field-tested structural logging.

  • Project Workbook now exports curated engineering columns, not cloud IDs and JSON import provenance; investigation-specific blank columns are omitted; searchable worksheet filters; structural resolved geological origin included; non-oriented Beta not represented as valid.
  • Spreadsheet importer recognises additional BH/TP column headings, keeps editable worksheet/header/field mapping, shows confirmation/preflight counts, automatically skips existing/overlapping geological and coring intervals, and aborts when a local pre-import checkpoint cannot be created. This release deliberately does not automatically merge or replace conflicting geology.
  • Omega multi-sheet importer now skips matching or overlapping geology records rather than appending known duplicates.
  • Structural form order puts Infill/Thickness before Gamma/Geological Origin.
  • Beta disabled for Spun/Not Oriented in add/edit; existing old Beta values preserved rather than destroyed; orientation confidence defaults remain.
  • Theme text contrast strengthened; JARVIS label replaced with Core Mode; branded app installation icon restored while the distinctive new tent/strata Core remains in sidebar as a responsive sync indicator.
  • Logger and Data Review editors now share ordered field definitions. Coring edit mirrors From/To, measured recovered lengths and fracture count, followed by calculated read-only Run Length / TCR% / SCR% / RQD% / FF and run comments.
  • Coring derived fields recalculate live and cannot be changed directly. On save, recovery totals are recalculated from measurements, invalid or overlapping intervals are rejected before mutating the original record.
  • Structural editing keeps the requested field order, orientation Beta lockout and controlled inputs.
  • Primary application icon remains the original StrataBase SB mark, including new padded maskable icons. The Core is a secondary navigation/status symbol.
  • Editing: field ordering now follows primary input order for coring, geology, structure, test pits, samples, groundwater, etc., where those fields are present. Coring editor computes run length and recovery percentages from editable depths/recovery totals; calculated fields are read-only. Coring edits validate against overlapping intervals and improbable measurements before saving.
  • Data Review shares the logging editor's input-field definitions. Recognised sample categories and groundwater rates retain dropdowns, and dates use date inputs.
